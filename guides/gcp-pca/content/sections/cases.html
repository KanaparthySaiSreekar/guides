Altostrat Media

A media company with a large library of podcasts, interviews, news broadcasts and documentaries. It wants generative AI for personalized recommendations, natural-language interaction and self-service support, and to grow revenue through dynamic pricing, targeted marketing and personalized suggestions.

Reliability and cost management are the top priorities.

Original PDF ↗

Existing environment

  • GKE runs content management and delivery.
  • The media library (documents, audio, video) is in Cloud Storage.
  • BigQuery is the main data warehouse for user behavior and audience data.
  • Cloud Run functions handle transcoding, metadata extraction and recommendations.
  • Legacy on-premises systems handle ingestion and archival, slated for migration.
  • Identity: Google Identity plus third-party identity providers.
  • Monitoring: Cloud Monitoring plus Prometheus, with alerts mostly by email.
RequirementLikely Google Cloud answer
Reliable workflows across Google Cloud and on-premisesOne fleet of GKE and Google Distributed Cloud clusters, Config Sync, SLOs, Managed Service for Prometheus, alerts routed to on-call channels
Simpler infrastructure, rapid deployment; modern CI/CD with centralized managementCloud Build, Artifact Registry, Cloud Deploy to every cluster; Autopilot or Cloud Run where possible; Terraform
Kubernetes that scales both on-premises and in the cloudGKE plus Google Distributed Cloud (software-only), managed together as a fleet
Secure, high-performance hybrid connectivity for ingestionDedicated or Partner Interconnect with MACsec or HA VPN over Interconnect; Storage Transfer Service agents
Lower storage cost for growing media, still highly availableAutoclass (or lifecycle rules for predictable patterns); dual- or multi-region for hot content; Cloud CDN or Media CDN for delivery
Natural-language interaction, 24/7 support, advanced chatbotsGemini-based agents on Agent Platform (ADK or Conversational Agents), grounded through Search or RAG Engine, with account APIs as tools and human handoff
Automatic summaries of diverse mediaGemini multimodal (audio and video input): batch inference for the back catalog, event-driven calls for new uploads
Rich metadata with NLP and computer visionVideo Intelligence, Vision, Natural Language, Speech-to-Text (Chirp), or Gemini multimodal; results stored in BigQuery
Detect and filter inappropriate content; AI-powered harmful-content detectionVideo Intelligence explicit-content detection or Gemini safety classification with human review; Model Armor on the chatbot
Auditable, explainable AIModel Registry versions, prompt and response logging, Data Access audit logs, Explainable AI, evaluation before release
Trends, insights, data-driven content strategyBigQuery with BigQuery ML and AI functions; Looker
Personalization and virality; targeted marketingRecommendations (Search for media, or BigQuery ML), Gemini for personalized content, audience segments in BigQuery
Mixed identity providersIdentity Platform for customers; Workforce Identity Federation or SAML SSO for staff

Likely question angles

  • Managing hybrid Kubernetes and centralized CI/CD
  • Choosing storage classes for unpredictable media access
  • Multimodal Gemini compared with single-task APIs
  • Content safety and Model Armor
  • Responsible AI: audit trails and explanations
  • Modernizing Prometheus and email alerting

Cymbal Retail

A fast-growing online retailer with a huge catalog across many sub-verticals. It has three initiatives: enrich the catalog with generative AI (attributes, descriptions, images from supplier data); conversational commerce with AI virtual agents that use Google’s Discovery AI; and a technical-stack modernization to cut manual work and costs.

Reduce call-center staffing costs and data-center hosting costs.

Original PDF ↗

Existing environment

  • A mix of on-premises and cloud systems.
  • MySQL, Microsoft SQL Server, Redis and MongoDB hold the catalog and customer data.
  • Kubernetes clusters run the containerized apps.
  • Legacy SFTP file transfers and ETL batch jobs.
  • Customers browse through SQL queries on product names and categories.
  • An IVR routes calls, and agents key in orders by hand.
  • Monitoring with Grafana, Nagios and Elastic.
  • Pain points: manual errors, data silos, hard integrations.
RequirementLikely Google Cloud answer
Attribute generation that matches the catalog structureMultimodal Gemini prompted with the taxonomy, structured output (response schema with allowed values), evaluation against labeled samples
Image generation and enhancement (colors, backgrounds, text overlays)Imagen editing on Agent Platform (mask-based editing, background replacement)
Natural-language product discoveryAI Commerce Search (formerly Vertex AI Search for commerce) with conversational commerce (Discovery AI)
Scale with the catalog without hurting performanceBatch inference for enrichment, managed search that scales with the catalog, autoscaling GKE or Cloud Run
Human-in-the-loop reviewStaging store plus a review app (Cloud Run behind IAP); publish only approved items; keep decisions for evaluation
Secure, compliant handling of customer and agent dataSDP de-identification of transcripts, Model Armor, tokenized payments (PCI scope), IAM, VPC Service Controls, CMEK
Lower call-center cost, replace the IVRConversational Agents (voice and chat) connected to order APIs; Agent Assist for human agents
Lower data-center hosting costCloud SQL (MySQL, SQL Server), Memorystore, Firestore with MongoDB compatibility or Atlas, GKE; then rightsizing and CUDs
Fewer manual processes, reliable data transfer and error handlingCloud Storage landing zone, Eventarc, Cloud Run functions or Dataflow, Pub/Sub, Application Integration, Apigee
Unified view of the customer journeyDatastream CDC into BigQuery; a customer 360 model
Proactive monitoring and securityCloud Monitoring and Logging, Managed Service for Prometheus (Grafana can stay), SLO alerts, Security Command Center

Likely question angles

  • A generative-AI enrichment pipeline with human review
  • Discovery AI compared with custom search
  • Automating the call center
  • Database modernization with minimal change
  • Protecting PII in conversational AI
  • Batch compared with online inference

EHR Healthcare

A software-as-a-service provider of electronic health records for medical offices, hospitals and insurers, growing exponentially. It needs to scale, adapt its disaster-recovery plan and adopt continuous deployment. Google Cloud will replace its colocation facilities.

Outages came from misconfigured systems, inadequate capacity for traffic spikes, and inconsistent monitoring.

Original PDF ↗

Existing environment

  • Several colocation facilities. One lease is about to expire.
  • Web-based customer apps, many now containerized on Kubernetes.
  • MySQL, MS SQL Server, Redis and MongoDB.
  • Legacy file- and API-based insurer integrations stay on-premises for now and will be replaced over several years.
  • Users are in Microsoft Active Directory.
  • Open-source monitoring. Email alerts are often ignored.
RequirementLikely Google Cloud answer
Onboard insurance providers quickly; ingest data from new providersApigee (API products, developer portal), Cloud Healthcare API (FHIR, HL7v2), Pub/Sub and Dataflow
At least 99.9% availability; lower latencyRegional GKE across zones, Cloud SQL HA, global external Application LB with Cloud CDN, a DR region
Centralized visibility, proactive action; consistent logging, retention, monitoring and alertingCloud Monitoring and Logging, aggregated sinks with retention, SLO burn-rate alerts to PagerDuty, shared dashboards
Healthcare insights, predictions, reportsHealthcare API streaming to BigQuery, de-identification, BigQuery ML or Agent Platform, Looker
Regulatory complianceHIPAA BAA, covered services only, VPC Service Controls, CMEK, Data Access audit logs, Access Transparency
Lower infrastructure administration costCloud SQL (MySQL, SQL Server), Memorystore, Firestore with MongoDB compatibility or Atlas, GKE Autopilot; DMS for the moves
Keep legacy insurer interfaces, connected to on-premises and cloudRetain them on-premises, with Interconnect, hybrid DNS and routing
Consistent management of container apps across environmentsGKE fleet, Config Sync, Policy Controller, one CI/CD pipeline (Cloud Build, Cloud Deploy)
Secure, high-performance on-premises connectionDedicated Interconnect from the colocation facilities (redundant), MACsec or HA VPN over Interconnect
Scale and provision new environments dynamicallyTerraform or Infrastructure Manager, a project factory, autoscaling
Active Directory usersGCDS to Cloud Identity plus SAML SSO (AD FS or Entra ID); Managed Microsoft AD for Windows workloads that need domain join

Likely question angles

  • Choosing between Interconnect and VPN
  • HIPAA prerequisites
  • Federating AD identity
  • Database migration before the lease ends
  • Fleet management for consistency
  • Alerting that people act on
  • DR plan design

KnightMotives Automotive

A car maker of autonomous, battery-electric, hybrid and combustion vehicles. Only its electric models have a modern in-vehicle experience, and sales of the others are falling. Within five years it wants a consistent, AI-powered “automotive experience” across all models, a reliable build-to-order system, better dealer tools, and new revenue from data monetization.

Security is a paramount concern after past breaches, and EU data protection compliance is critical.

Original PDF ↗

Existing environment

  • Mostly on-premises, with some apps on major public clouds.
  • The supply chain runs on an outdated mainframe, and the ERP is outdated.
  • Dealers have no budget for new equipment.
  • Fragmented vehicle code bases and heavy technical debt.
  • Weak connectivity to plants and to vehicles in rural areas.
  • Obsolete AI infrastructure and siloed corporate data.
RequirementLikely Google Cloud answer
Consistent AI-powered in-vehicle experience, reliable connectivity including rural areasEdge models in the vehicle, store-and-forward uploads to Pub/Sub, idempotent cloud processing, cloud agents grounded on vehicle data
Network upgrades between plants and headquartersCloud Interconnect at major sites, Network Connectivity Center hub, SD-WAN router appliances, Google Distributed Cloud at plants
Hybrid cloud, gradual legacy modernizationMainframe APIs through Apigee, Mainframe Connector to BigQuery, strangler-pattern replacement, SaaS ERP evaluation, fleets across environments
Autonomous development: AI/ML, simulation, regulatory complianceAI Hypercomputer (GKE or Cluster Director with GPUs or TPUs, DWS), Batch with Spot for simulation, Agent Platform Pipelines and Model Registry for traceability
Data monetization: data platform, security and privacy, scalable AIBigQuery as the platform, Knowledge Catalog (formerly Dataplex) governance, SDP de-identification, BigQuery sharing and data clean rooms
EU data protectiongcp.resourceLocations or Assured Workloads for EU, CMEK or EKM, regional AI endpoints, pseudonymization
Security framework, incident response, awareness trainingSCC Enterprise, Google SecOps (SIEM and SOAR playbooks), Mandiant, VPC Service Controls, Chrome Enterprise Premium, training through Google Skills
Better online build-to-orderCloud Run or GKE services, Spanner for consistent orders and inventory, Pub/Sub integration with ERP, Apigee for dealers
Modern dealer tools with no new hardwareBrowser and mobile apps on Cloud Run, Identity Platform or IAP for dealer sign-in
Comprehensive CRMBuy a SaaS CRM; integrate it with Application Integration or Integration Connectors and BigQuery
Upskilling, talent, business-tech communicationA cloud center of excellence, Google Skills paths, architecture reviews with business stakeholders, Gemini Enterprise for shared knowledge

Likely question angles

  • EU residency and sovereignty
  • Data monetization without exposing personal data
  • Designing for disconnected edges
  • Hybrid networking with NCC
  • Choosing accelerators and consumption models
  • Buy vs build (CRM, ERP)
  • Modernizing the mainframe gradually
  • Security operations after breaches
